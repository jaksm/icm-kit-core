# 0.1.0 to 0.2.0

## What changed and why

Setup arrived: a skill that stands up an ICM from the template, or adopts one that exists. With it
came the catalog of optional workflows, a recovery USB, and a rule for the owner's changes to core
files. Nothing that worked in 0.1.0 moved.

## Moved or renamed

Nothing.

## Outside core/

1. New, optional: `_config/overrides/<path of a core file>`. If you edited a file inside `core/`,
   `install.sh` reports it. Move the edit there instead of keeping it in `core/`; see
   `core/adapters/claude/recipes/customize.md` for which code looks at overrides.
2. `core.lock` may now hold `module <name>` lines for workflows installed from the catalog.
   `install.sh` writes them; nothing to do by hand.
3. An ICM that predates setup: run the `setup` skill once. It detects what already stands, records
   it in `_config/setup.json` with evidence, and only walks through what is missing (usually the
   backup and the catalog).

## Verify

```bash
<release>/install.sh . --status        # installed 0.2.0, the catalog listed, no locally edited files
ls core/skills/setup/steps | wc -l     # 10
bash -n core/backup/make-usb.sh
```
