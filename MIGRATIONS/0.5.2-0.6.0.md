# 0.5.2 to 0.6.0

## What changed and why

The pages got one design language of their own instead of borrowing the host application's, and the three page
templates (feed, expenses, graph) were rebuilt from the library's composable primitives, so they hold only what is
particular to each page. Every page looks different after this update; no data, config key or label changed.

## Moved or renamed

| Was | Now |
| --- | --- |
| `core/ui/tokens/palettes/` | gone: one palette, in `core/ui/tokens/colors.css` |
| `core/ui/workbench/`, `core/ui/concept/` | `core/ui/docs/index.src.html`, built with `python3 core/ui/build.py --docs` |
| category colors written in `build-expenses-page.py` and `graph-template.html` | `--cat-1..12` in `core/ui/tokens/data.css` |
| the feed's own scrim gradients and ground color | `--scrim-*` and `--ground` tokens |

## Outside core/

Nothing, unless you keep your own copy of a template in `_config/overrides/core/workflows/<name>/template/`. That copy is
the OLD template and will keep the old markup on top of the new library, where components no longer carry outer margins
and the serif font is gone, so it will look broken. For each such file:

```bash
git diff --no-index core/workflows/<name>/template/<name>-template.html _config/overrides/core/workflows/<name>/template/<name>-template.html
```

Move what you changed (usually a few rules or a label) onto a fresh copy of the new template, and delete what you did not
change. The feed builder still refuses a template that lost one of the rules it depends on (`--check` names it).
A page you published earlier keeps its old look until you build and publish it again.

## Verify

```bash
<release>/install.sh . --status                                   # 0 locally edited files
python3 core/workflows/graph/scripts/build-graph-page.py --demo   # and the same for every workflow you installed
```

Open the pages it names: they are built from mock data, so they show the new look without your base. Then build your own
pages as usual.
