# 0.7.3 to 0.8.0

The kit no longer ships a component library (`core/ui`) or the `feed` workflow. Pages are single
self-contained HTML files the agent publishes as plain artifacts, following the harness's own
artifact guidance.

## Outside core/

1. **Feed**: the workflow is gone from the catalog. `install.sh` removes `core/workflows/feed/`
   on update (an edited file is kept as `.local`, resolve or delete it). Your feed record, its
   diary and its data stay where they are in your ICM; nothing there is touched. The archive of
   the code is private to the author. Delete `_config/feed.json` if present, and the feed's rows
   in the instruction file, `skills/CONTEXT.md` and `domains/system/output/pages.md`.
2. **Rebuild the graph and the expenses page**:
   ```bash
   python3 core/workflows/graph/scripts/build-graph-page.py --check
   python3 core/workflows/expenses/scripts/build-expenses-page.py    # if expenses is installed
   ```
   then republish each to its existing URL. A page built with the old library still opens as it
   is, but it is not rebuilt: the next build uses the new template.
3. A changed copy of a template in `_config/overrides/` was written against the library's classes
   and the `/*ICM-CSS*/` slot, which no longer exist. Start again from the new template.
4. Anything of yours that imported `core/ui/build.py` (a page builder in your `skills/`) has to
   carry its own stylesheet now: `grep -rn "core/ui" --exclude-dir=core .`

## Verify

```bash
./core/scripts/style-check.sh          # no template rule about core/ui any more
ls pages/graph.html                    # rebuilt, and the page opens in light and dark
grep -rn "core/ui\|catalog/feed" --exclude-dir=core .   # nothing
```
