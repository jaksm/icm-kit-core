# 0.4.0 to 0.5.0

## What changed and why

The catalog has `feed`: the funnel of signals, media, and the page of reels, as ready code. With it
every workflow that was promised in the catalog exists. Nothing that worked in 0.4.0 moved.

## Moved or renamed

`core/workflows/sources/scripts/check-feed.py` is now `core/scripts/check-feed.py`, installed with every
ICM, because the feed needs it without the mail workflow. `install.sh` moves it; a routine prompt or
an owner's skill that names the old path must be edited.

## Outside core/

Nothing is required. Optional: `<release>/install.sh . --add feed`, then `core/workflows/feed/setup.md`.

An ICM that already builds a daily page of its own can run this one **beside** it: point `data`,
`media_dir` and `out` in `_config/feed.json` at folders the old page does not write, build with
`--preview`, and compare. The feed's vocabulary is feed, row, card: a day file holds `rows`, each with a `cover` and `stories` (its cards). A day written with `reels` is still read. Otherwise day files in the shape of `core/ui/schema.json` need no conversion. Note
that a build writes `prints` and `build` back into the day file it was given, so compare on a copy.
The diary this page writes uses English keys (`items`, `liked`, `detailsMs`); an older diary under
other names stays readable in the store and is not merged.
